# FloderSync 需求规格（草案）

状态：MVP 基线已确认（2026-09-02）  
目标平台：macOS

## 1. 产品目标

FloderSync 是一个常驻菜单栏的 macOS 工具。它管理多个本地文件夹与 Git 仓库的映射，复用机器上已有的 Git 命令和认证配置，按自动或手动策略完成提交、拉取与推送，并清楚呈现当前状态和可恢复的错误。

## 2. 用户与核心场景

主要用户是已经会在终端中配置 Git 和远端认证、但希望日常文件同步自动完成的个人用户。

核心场景：

- 为多个本地 Git 工作区引用可复用的自动化规则，或分别配置自定义同步策略。
- 在约定时间、固定间隔或文件发生变化后自动同步。
- 从菜单栏查看全局状态，并一键同步全部或单个仓库。
- 在独立设置窗口中编辑仓库、自动化与应用设置。
- 登录 macOS 后自动启动并在后台运行。
- 同步失败时看到可理解、可行动的原因，而不是静默丢失数据。

## 3. MVP 功能范围

### 3.1 仓库配置

每个同步配置（`SyncProfile`）至少包含：

- 唯一标识与显示名称。
- 本地工作区路径。
- 远端名称，默认 `origin`。
- 目标分支策略，建议 MVP 使用“当前检出分支”。
- 是否启用。
- 一组同步触发策略。
- 自动化配置来源：共享规则或仓库自定义配置。
- 远端整合策略：Rebase 或 Merge，默认 Rebase。
- 自动提交开关、提交者名称与邮箱、提交信息模板；提交者留空时按仓库配置、Git 全局配置的有效值回退。

推荐的 MVP 边界：用户选择的目录必须已经是可工作的 Git 仓库，并已配置远端与认证。应用负责验证，不在 MVP 中负责 `clone`、`init`、创建远端或管理密钥。

### 3.2 同步触发

- 手动同步：菜单栏中支持“同步全部”和“同步单个仓库”。
- 指定时间：每天一个或多个本地时间点；是否支持星期筛选待确认。
- 固定间隔：按分钟或小时配置；推荐从上一次同步完成时间计算。
- 文件状态检测：使用文件系统事件触发，去抖后运行 Git 状态检查；忽略 `.git` 内部事件，只有 Git 认为工作区有变化时才同步。
- 同一仓库的并发触发合并为一次后续同步，不并行执行 Git 操作。
- 文件变化同步支持 5 秒、10 秒、1 分钟和自定义静默延迟。
- 自动化规则可以被多个仓库引用；保存规则变更后，所有引用仓库从下一次触发开始使用新配置。

### 3.3 建议的同步语义

MVP 默认采用保守、可解释的流程：

1. 校验目录、Git 可执行文件、仓库、分支与远端。
2. 获取工作区状态。
3. 如果有本地变化且自动提交已开启，执行 `git add -A` 并创建自动提交；关闭时停止并提示用户先手动提交。
4. 从远端拉取，并按照仓库的有效自动化配置使用 rebase 或 merge 整合；默认使用 rebase。
5. 推送当前分支。
6. 记录每一步的脱敏结果、耗时和最终状态。

安全规则：

- 不自动执行破坏性恢复，例如 `reset --hard`、强制推送或自动丢弃冲突文件。
- 遇到合并/rebase 冲突、detached HEAD、认证失败、非 fast-forward 等情况立即停止并提示用户处理。
- 自动任务采用非交互模式，不弹出终端认证询问；认证不可用时给出诊断信息。
- 提交信息既可为固定文本，也可使用 `${user}`、`${email}`、`${time}`；应用级作者覆盖只用于本次提交，不修改仓库或全局 Git 配置。
- Git LFS 与 submodule 在 MVP 中只透传系统 Git 行为，不额外管理；具体支持级别待确认。

### 3.4 状态与历史

菜单栏至少展示：

- 全局状态：空闲、同步中、部分失败、全部正常。
- 每个仓库：最近结果、最近成功时间、是否有待同步变化。
- 快捷操作：同步全部、同步单个仓库、打开设置、快速添加仓库。

设置窗口至少包含：

- 仓库：新增、编辑、禁用、移除和连接检查。
- 自动化：时间、间隔、文件变化策略。
- 通用：登录时启动、通知和语言信息；入口固定在侧边栏底部。
- 历史与诊断：最近同步记录、失败步骤、可复制的脱敏日志。
- 退出：固定在侧边栏底部，不占用菜单栏弹窗的高频操作空间。

设置侧边栏常驻且不可折叠；“通用”和“退出”在底部横向分布。首次添加仓库时必须先验证目录和远端配置；若本地 HEAD 与远端分支不一致，询问用户是否立即同步，用户也可以稍后按已配置计划执行。语言支持跟随系统、英文和简体中文，切换后当前界面立即更新。

同步失败、冲突或需要人工处理时，菜单栏图标、菜单栏仓库行和设置仓库列表都必须显示非纯颜色的错误标识，并明确提示用户手动处理。

设置窗口采用无文字标题栏的沉浸式样式：保留 macOS 原生窗口控制按钮，隐藏“FloderSync 设置”标题及独立标题栏背景。窗口内容使用更大的连续圆角；左侧为带外边距的浅色圆角导航卡片，不显示 FloderSync 标题。侧边栏底部的通用与退出只显示图标，不使用独立底栏背景，同时必须保留 tooltip、键盘焦点和 VoiceOver 标签。

窗口不得保留会遮挡内容的原生标题栏占位。侧边栏只允许蓝色填充表示当前模块，不显示额外键盘焦点边框；使用 Tab 将焦点移到仓库、自动化、历史与诊断或通用时，应同时切换到对应模块。通用设置提供跟随系统、浅色与深色三种主题，切换后菜单栏和设置窗口立即更新并在重启后保留。

设置窗口必须从首帧起使用沉浸式窗口结构：保留系统红黄绿窗口控制按钮，但不显示独立标题栏背景、标题栏安全区或主题切换时的异色闪烁。不得依赖窗口显示后再异步修正样式。

菜单栏使用 FloderSync 自有的“文件夹 + 双向轨道箭头”符号，不直接使用通用 SF Symbol。图标采用接近 1:1 的方正视觉占位和保留原色的蓝青渐变矢量，箭头只轻微越过文件夹两侧；线条在 Retina、浅色与深色菜单栏的 16–18pt 尺寸下保持精细且清晰。同步中和失败状态通过不破坏主轮廓的小型蓝色、红色状态点表达。README 必须展示相同结构的品牌图标，并提供内容等价、可互相跳转的英文与简体中文版本。

### 3.5 登录启动与后台行为

推荐 MVP 是“用户登录会话内的菜单栏应用”：

- 通过系统 Service Management API 注册登录启动。
- 应用退出后不再同步；机器睡眠时不运行。
- 从睡眠恢复后，根据已确认的补偿策略决定是否执行错过的定时任务。
- 不使用 root daemon，不要求管理员权限。

## 4. 非功能需求

- 数据安全：不保存 Git 密码、Token、SSH 私钥；日志默认脱敏远端 URL 中的凭据与敏感参数。
- 可靠性：每个仓库串行同步；进程退出、超时和取消均有明确状态；应用崩溃后可恢复到一致状态。
- 性能：空闲时不轮询 Git；文件变化事件需要去抖和合并。
- 可访问性：支持 VoiceOver、键盘导航、增大对比度、减少动态效果、浅色/深色模式。
- 可维护性：核心领域逻辑不依赖 SwiftUI、`Process`、FSEvents 或具体存储实现。
- 可诊断性：每次运行具备 run ID、触发来源、分步骤耗时和标准化错误类别。
- 本地化：首版支持简体中文和英文；所有用户可见文案必须走本地化资源，缺失翻译时回退英文。

## 5. 建议暂不纳入 MVP

- 应用内 Git 账号、SSH Key、PAT 或 OAuth 管理。
- 自动解决冲突、强制推送、历史改写策略编辑器。
- 远端仓库创建、仓库托管平台 API 集成。
- 多设备编排、云端账户与云同步配置。
- root daemon 或无用户登录时运行。
- 仓库浏览器、差异编辑器和完整 Git GUI。

## 6. 已确认的产品决策

1. 本地目录仅接受已有 Git 仓库；MVP 不负责 clone、init 或创建远端。
2. 同步算法为 `add/commit -> pull -> push`；pull 支持 Rebase 和 Merge，默认 Rebase。
3. 冲突时停止并通知用户手工处理，不做自动恢复或强制推送。
4. 仅在用户已登录且应用运行时同步，不引入 daemon。
5. 唤醒或重新启动后补执行最近一次错过的任务，同一配置只补一次。
6. 文件变化停止一段可配置的静默延迟后触发检查；默认 5 秒，并提供 10 秒、1 分钟和自定义时长。
7. 支持每天多个本地时间点、固定间隔和文件变化，不支持 cron 表达式或星期筛选。
8. 使用当前检出分支，不由应用自动切换分支。
9. 采用 Developer ID 签名、公证和直接分发，不以 Mac App Store 为首发渠道。
10. 最低支持 macOS 14；新系统视觉渐进增强，旧系统使用原生降级表现。
11. 默认仅在失败、冲突或需要用户操作时发送通知。
12. 首版支持简体中文和英文。

## 7. MVP 验收摘要

- 可配置至少 10 个现有本地 Git 仓库，分别启用不同触发策略。
- 手动与三类自动触发都能进入统一同步引擎。
- 已配置好的 SSH 或 HTTPS 凭据在非交互环境可用时，应用不要求再次保存认证。
- 本地和远端无冲突时完成提交、rebase/pull 与 push。
- 冲突或认证失败时不破坏工作区，UI 能指出仓库、失败步骤和建议操作。
- 登录启动状态与系统设置一致，菜单栏和设置窗口均可访问。
