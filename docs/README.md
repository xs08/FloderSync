# obsSync 设计与交付文档

状态：需求与架构基线已确认，进入实现  
最后更新：2026-09-02

本目录定义 obsSync 从需求到实现的交付链路。在需求和架构决策被确认前，不进入核心实现。

## 交付链路

1. [需求规格](./01-requirements.md)：确认产品范围、同步语义、异常行为与验收标准。
2. [架构设计](./02-architecture.md)：确认平台边界、模块职责、数据流与关键技术决策。
3. [功能测试方案](./03-test-plan.md)：在编码前把验收条件落实为可执行测试。
4. [实现路线图](./04-implementation-roadmap.md)：按风险和依赖拆分实现阶段并记录进度。
5. [验证记录](./05-verification.md)：记录自动化证据、环境限制和发布前验证矩阵。

## 阶段门

| 阶段 | 进入条件 | 退出条件 |
| --- | --- | --- |
| G0 需求澄清 | 初始需求已记录 | `01-requirements.md` 的开放问题均有结论 |
| G1 架构确认 | 产品范围冻结 | 关键 ADR、模块边界和数据模型已确认 |
| G2 测试设计 | 架构确认 | P0/P1 用例、集成测试夹具和 UI 验收项已确认 |
| G3 核心实现 | 前三项完成 | MVP 功能完成并通过对应测试 |
| G4 发布准备 | MVP 验收通过 | 签名、公证、升级与回滚路径验证完成 |

当前阶段：G3 核心实现。G0、G1、G2 已于 2026-09-02 按推荐方案确认。

任何需求变更都先更新需求文档，再检查架构与测试是否需要同步修改。
